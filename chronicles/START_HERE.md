# Eternal Chronicle 12.0 — вход для нового чата

Репозиторий Aspksa/Tenmatsuyora, ветка main. Роман — вымышленное произведение, не биография пользователя и не память основного чат-агента. ChatGPT пишет по команде автора. Никаких автоматических запросов Cloud.ru.

## Обязательный порядок
1. Получи SHA актуальной main и читай все файлы по этому SHA, не смешивай ветки. Проверь открытые PR с главами. Не дублируй их.
2. Прочитай AGENTS.md в этой папке, state/checkpoint.json, state/current.json (при большом объёме — только нужные state/characters/ID.json), catalog.json, canon/foundation.json, style/STYLE.md, style/VOICES.md, plan/PLOT.md и plan/UNKNOWN.md.
3. Прочитай последние 2–3 полные главы из catalog.json и их записи events. Для старых фактов ищи по персонажу, месту, событию, словам и сюжетным линиям; обязательно открой исходную главу. При наличии локального Python используй scripts/chronicle.py context/search/validate. В новом чате без терминала пользуйся индексом и файлами GitHub непосредственно.
4. Восстанови текущие знания каждого героя, местонахождение, физическое состояние, отношения (A→B отдельно от B→A), предметы, обещания, тайны, правила магии. Безграничную силу императрицы не ограничивай; прямое прикосновение вызывает шок у живого существа; единственное авторски разрешённое будущее исключение — Антон, см. plan/PLOT.md. До раскрытия не превращать исключение в знание героев. Не путай планы с каноном.
5. Если есть конфликт с источниками, остановись на конфликтной детали, не выдумывай разрешение. Если критического конфликта нет, составь план сцены и продолжай.
6. Напиши следующую полноценную главу прозы без заданного лимита объёма. Заголовок отдельно. Не дроби на искусственные короткие эпизоды ради объёма. При ограничении контекста сохраняй черновик в отдельной ветке, НЕ публикуй недописанное.
7. Добавь главу, запись в catalog.json, соответствующий events/*.json, обнови state/checkpoint.json, state/current.json и state/characters/*.json и plan/PLOT.md при необходимости. Все изменения — одним PR. Сохраняй ссылки на реальные сцены; не объявляй непроизошедшее фактом.
8. Пройди checklist и проверку Python/CI; проверь литературные противоречия вручную. Не заявляй, что тесты проверили психологию. Слияние только после разрешения автора (может быть дано текущей командой или постоянной инструкцией на этот цикл) и успешного CI. Если main изменилась, прочитай новую версию; не перезаписывай.
9. После merge сообщи номер главы, PR, SHA и состояние. Новый чат начнёт с пункта 1. Не рассчитывай на память прошлых чатов.

Входная команда: «Продолжи роман Tenmatsuyora: прочитай chronicles/START_HERE.md в актуальной main, восстанови канон и стиль, напиши следующую большую главу, обнови память, проверь и слей в main».

## Narrative Intelligence 13.0 — обязательное дополнение
Перед планом новой главы прочитай narrative/handover/latest.json, narrative/manifest.json, narrative/index.json. Это проверяемые производные от журнала, не самостоятельный канон. Прочитай нужные narrative/characters/ID.json, narrative/pairs/ID--ID.json, narrative/threads/ID.json, commitments и secrets; по event ID из индекса открой narrative/chapters/NNNNNN.json, затем оригинальный абзац главы. Не загружай весь роман. Сначала обязательные источники, затем релевантные. CLI: python scripts/chronicle.py retrieve "тема" --character char.tenmatsuyora --character char.other (ID — только существующие). Если есть graph_truncated, расширь выборку источников вручную; отсутствие результата не означает отсутствие события. Перед началом составь краткую карту кто что знает, последнего контакта пары, открытых обещаний, эмоциональных состояний и перехода от точного последнего абзаца. Если речь идёт о далёком эпизоде, прочти его источник, а не пересказ. При новом черновике не продолжай из недоверенной ветки без проверки SHA базовой main и номера главы.
После написания добавь точные источники событий и разметку сцен, диалоги, причины, последствия, обновления знаний и обязательств, затем stamp и validate. Файлы narrative/ генерируются и сравниваются в CI. Без локального терминала получи JSON из доступного инструмента или подготовь черновой PR и сообщи, что генерация снимков ещё нужна; не подделывай хеши. Если конфликт критический, не публикуй. GitHub не выполняет передачу контекста в новый ChatGPT автоматически.
